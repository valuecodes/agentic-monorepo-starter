# AGENTS.md

Guidelines for AI agents and contributors working in this Turborepo monorepo.

`CLAUDE.md` is a symlink to this file. Never edit `CLAUDE.md` directly.

---

## Structure

### Apps (`apps/`)

| Name       | Filter       | Description                                                     |
| ---------- | ------------ | --------------------------------------------------------------- |
| playground | `playground` | Vite 8 + React 19 app for experiments, deployable to Cloudflare |

### Packages (`packages/`)

| Name       | Filter             | Description                                                      |
| ---------- | ------------------ | ---------------------------------------------------------------- |
| logger     | `@repo/logger`     | pino logger emitting Cloud Logging shaped JSON                   |
| typescript | `@repo/typescript` | Shared tsconfig presets (`base.json`, `node.json`, `react.json`) |

CI helpers are not workspaces: the composite setup action lives in
`.github/actions/setup/` and the gitleaks script in `.github/scripts/`.

Apps may import packages; packages must never import apps. oxlint bans `../`
imports and deep `@repo/*/src` imports: import other workspaces by package name,
and inside an app use the `~/` alias (`src/*`) to go up the tree.

## Commands

**Prerequisites:** Node.js 26 (exact version in `.nvmrc`), pnpm 12 (exact version in `packageManager` in root `package.json`).

```bash
pnpm install                     # Install all dependencies
pnpm --filter playground dev     # Vite dev server (port 3000)

pnpm lint                        # oxlint, one process over the whole repo
pnpm knip                        # unused files, exports and dependencies
pnpm typecheck                   # turbo run typecheck
pnpm test                        # turbo run test
pnpm build                       # turbo run build
pnpm format                      # oxfmt, writes in place
pnpm format:check                # oxfmt --check (no writes)
pnpm secrets:scan                # gitleaks over the full git history
pnpm clean                       # turbo run clean
```

`lint` and `knip` do not go through Turbo — each is a single process over the whole
repo. oxlint is configured by the root `.oxlintrc.json` (including `import/no-cycle`)
and prints nothing when there are no findings, so silent output means clean. Knip is
configured by the root `knip.jsonc` and exits 0 when clean. Formatting is oxfmt
(Prettier-compatible), configured by the root `.oxfmtrc.jsonc`, which also sorts
imports and Tailwind classes.

Nothing formats on edit, and the pre-commit hook only checks formatting: run
`pnpm format` yourself before committing.

Git hooks live in `.githooks/` and are plain shell scripts, with no hook manager.
`pnpm install` enables them through the root `prepare` script. The setting goes in
the clone's shared git config, so it covers every worktree, and a branch without
`.githooks/` simply runs no hooks. If you cloned before the hooks existed and have
not run `pnpm install` since, run `git config core.hooksPath .githooks` once. `pre-commit` runs `format:check`, `lint` and `secrets:scan --staged`. The
secrets scan fails closed, so the commit is refused when neither gitleaks nor
Docker is available. `pre-push` runs `typecheck`, `test` and `knip`. CI still
runs every check. `format:check` and `lint` read the working tree, not the staged
snapshot, so stage everything you mean to commit.

`secrets:scan` runs gitleaks (`.github/scripts/secrets-scan.sh`, version pinned
there) using a local `gitleaks` v8.19+ if one is on PATH, otherwise the pinned Docker image.
It exits 0 when clean and 1 when it finds a leak.

CI checks are defined once in the reusable `.github/workflows/checks.yml`: typecheck,
lint, knip, format:check, test, build, secrets-scan, CodeQL code scanning
(`javascript-typescript`) and workflow-lint. `feature.yml` calls it on PRs and
`main.yml` on push to `main` (deploy jobs go there). workflow-lint calls the reusable
workflow from `valuecodes/automation`: actionlint (with shellcheck) and zizmor over the
workflow and action files. Each tool reads `.github/actionlint.yaml` / `zizmor.yml` if
added. `all-passed` in `feature.yml` fans the checks in and is the one check to require
in branch protection. The typecheck, test and build
jobs restore Turbo's `.turbo` cache from the previous run of the same task, so
unchanged packages replay instead of rerunning.

`.github/workflows/actions.lock` is the GitHub Actions workflow lockfile (public
preview). It is machine-generated by the `github/gh-actions-lock` gh extension and
pins every action a workflow uses, including the ones called by other actions, to a
commit plus the owner and repo ids, so a commit that only exists in a fork is
rejected. Never edit it by hand. The `actions-lock` job runs
`gh actions-lock --verify`, and the runner checks the lockfile again when each job
starts. After adding a workflow or changing any `uses:`, install the extension at
the version pinned in `checks.yml` (`gh extension install github/gh-actions-lock
--pin <ver>`) and rerun `gh actions-lock` from the repo root; commit the workflow
and the lockfile together. Because the lockfile holds the commit, `uses:` lines
carry release tags, not SHAs, and the lockfile diff is where a version bump is
reviewed. Dependabot keeps existing entries current in its own bump PRs but never
adds new workflows or `uses:`. Reusable workflows called from `valuecodes/automation`
(`jobs.<id>.uses`) are not covered; only their full-SHA pins protect them. The
local composite action is referenced as `$/.github/actions/setup` so its actions
are locked too; `.github/actionlint.yaml` silences actionlint's complaint about
`$/` and `zizmor.yml` accepts tag refs, both until those tools understand the
lockfile. The extension version is bumped by hand (the maintenance dashboard does
not track it). Being a preview, expect an occasional relock or lockfile format
change: an exit 2 "lockfile version newer than the extension" means bump `--pin`.

Dependabot (`.github/dependabot.yml`) bumps the actions and reusable workflows
monthly in one grouped PR, updating the lockfile entries along with them; npm
dependencies are updated by hand.

`maintenance-dashboard.yml` calls the maintenance dashboard workflow from
`valuecodes/automation` daily.
It keeps one issue, **Maintenance dashboard** (label `maintenance-dashboard`), listing
what is due: `catalog:` updates, pnpm (`packageManager`), gitleaks (`GITLEAKS_VERSION`
in the secrets-scan script), Node.js (`.nvmrc`) and `pnpm audit` findings. Like
`minimumReleaseAge`, a release shows up only once it is 14 days old; a Node.js security
release shows up right away and is flagged. It never opens PRs or commits.

`maintenance-updates.yml` calls the maintenance updates workflow from
`valuecodes/automation` weekly. It keeps one PR per kind open (Node.js, pnpm,
gitleaks, `catalog:`) on a `maintenance-updates/<kind>` branch, for updates on the
current major only; majors stay manual. Those PRs are opened with `GITHUB_TOKEN`, so
their `pull_request` checks wait until someone with write access clicks **Approve
workflows to run** in the PR. It needs **Allow GitHub Actions to create and approve
pull requests** turned on under Settings → Actions → General. Nothing auto-merges. After merging a Node.js or pnpm update, set the Cloudflare `NODE_VERSION`
or `PNPM_VERSION` build variable to match. If `GITLEAKS_VERSION` moves out of
`.github/scripts/secrets-scan.sh`, pass the new path as the `gitleaks-script` input to
both callers. The dashboard, updates and workflow-lint callers pin the same
`valuecodes/automation` commit, so bump them together.

## Rules

- Keep diffs tight and focused; no drive-by refactors or new tooling without discussion.
- Never commit secrets, credentials, or `.env` files. All code must be public-safe.
- Never bypass the git hooks with `--no-verify`; fix the failure instead.
- Add dependencies to the correct workspace with `pnpm --filter <package> add <dep>`.
  Every external version lives in the `catalog:` block of `pnpm-workspace.yaml`
  and manifests reference it as `catalog:`; `@repo/*` deps stay `workspace:*`.
  Update with `pnpm up --latest -r`; `updateConfig.ignoreDependencies` holds
  `@types/node` to the `.nvmrc` major, so bump it by hand.
- Every install enforces the supply-chain settings in `pnpm-workspace.yaml`
  (`minimumReleaseAge`, `trustPolicy: no-downgrade`, `engineStrict`) plus pnpm
  12's default `blockExoticSubdeps`. When one fails, investigate: never disable
  it, and never exclude a whole package to get past it.
